# R41f notes (Claude, 2026-11-01, branch lite/r41e)

1. **Swipe back.** Safari 26 (Anh's phone) plays its own swipe animation and then fires popstate with `hasUAVisualTransition` true. Now: true -> no glide, no hold, no shrink: land straight in the strip (`back(false, instant)` -> `finishBack(..., instant)` takes the existing no-animation path). false (browser Back button, older Safari) -> unchanged glide (cap 0.3 s) + shrink. The wait for a missing back renderer is capped at 400 ms (was 3000 ms): after that the flat picture shrinks, so nothing can hold the screen again. NOT reproduced (no iOS / WebKit here): Anh checks by eye. If the swipe still shows a hold, the next step is the perf report's `lastBack` marks.
2. **Open frames.** A tap before the idle build finished built the page in one block mid-flight; now one build / prime step per frame over the flight (landing waits for the last one). `show()` (Lenis, ScrollTrigger refresh, resize re-measure, nav) was one block at the landing; it is now 3 frames (async). Chromium 6x, tap 2.5 s after a flick: worst open frame 51-87 ms, 1 frame over 33 ms (before: 62-80 ms, 1-3 frames). That frame is at click + ~55 ms (flight start, with the title play just before it), not a page build; no JS long task over 50 ms in the profile. Not at target on this proxy; the phone report decides.
3. **Title.** The leave is now immediate (opacity 0, no 0.2 s CSS fade) the frame the strip stops being "stopped". `?perf` report field `titlePlays` logs layout / play / hide / cancel with reasons. Play times are identical to R41e (no added delay). Double play: not reproduced; one candidate was `layout()` -> `smear.cancel()` on iOS toolbar resizes mid-play: layout now skips when the size did not change.
4. **Black on reload** (not changed): the project page keeps its black overlay until the header picture is decoded AND the flight hand-off finished (project/desktop.js, `ready` + `__pxtFlightDone`); on a cold reload that is the network fetch + decode of the header. Unmeasured.
