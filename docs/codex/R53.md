## Steps (one commit per step, push after each)
1. Strip loading while a project is open (core.js). `idleLoad()` and the phone activation stagger (`mode.tap` setTimeouts near the end of
   the load code) do not check `paused`, and rest stays "ok" while paused (the tick is removed, so `stillSince` freezes). Fix: in `pause()`
   call `rest.interrupt()`; in `idleLoad`'s step treat `paused` like `TC.on` (wait and retry later, do not activate); the tap stagger skips
   while `paused` and the remaining items are picked up by `idleLoad()` after `finish()` (which already calls it). Nothing changes at rest.
2. iPhone hero frame (home-handoff.js `saveHeroFrame`). Keep the current path first. If `createImageBitmap` / `OffscreenCanvas` /
   `convertToBlob` is missing or throws, fall back to a plain 2D `<canvas>`: `drawImage(video, 0, 0, w, h)` + `toDataURL('image/jpeg', 0.82)`,
   then `writeHeroFrame`. Same size and quality as now. Also make sure navigation does not cut the save off: `home-leave.js` keeps the promise
   and awaits it after the flight with a 150 ms cap (`Promise.race`), so the flight timing never changes. Log which path ran with ?debug=handoff.
3. GPU leaks on rebuild (cards-gl.js, smear.js, frame-gl.js).
   a) The per-video `requestVideoFrameCallback` loop in cards-gl.js keeps re-arming forever, also after `destroy()`, and a renderer rebuild
      (context loss retry in core.js `startRenderer`) starts a second loop on the same <video>. Keep the callback handle, stop re-arming when
      `!api.active` or the context is lost, and `cancelVideoFrameCallback` it in `destroy()`.
   b) `destroy()` also clears the warm-up `setTimeout` (store its id).
   c) smear.js `destroy()` must release its WebGL context the same way the others do (`glClose(gl, 'title')` from util/gl-ledger.js), after `finish(true)`.
   d) Where a shader link fails and the function returns null (cards-gl.js, frame-gl.js), call `glClose` on that context first.
   Do NOT add per-texture deletes before `glClose`: losing the context frees them (the review's other suggestion is not needed).
4. Phone menu takeover hang (tall-menu.js `takeOver`). If the burger is tapped during the takeover close, `pending` reopens the menu and the
   50 ms poll never resolves, so `window.__siteReady` and the Home flight setup never run. Fix: while `takingOver`'s close sweep runs, a burger
   tap is ignored (not queued), and resolve from the end of that close sweep instead of polling (remove the setInterval). Same look.
5. Text measuring (tall-details.js `ink`, tall-menu.js `inkOf`). One module-level 2D context per file, created on first use and reused (set
   `font` each call as now). Results must be identical: compare the `ink()` outputs for every call in one layout() before and after (log both, 0 difference).
6. Dead code.
   a) tall-menu.js: use `hcmcTime` (and the minute tick if it fits without a behaviour change) from src/util/clock.js instead of its own copy;
      remove the stale "should import this file" note in clock.js.
   b) page-swap.js: remove the empty `warmNext` and its call.
   c) `uPinchDown`: declared in warp-shader.js and set in cards-gl.js / frame-gl.js but never read in the shader body: remove all three.
      `uZoom` IS used in frame mode (R16g cover zoom): keep it.
   d) work/index.html: the R45c3 comment describes a `<link rel="expect" href="#pxh" blocking="render">` that is not in the file
      (index.html has one for #pxg). Do NOT add it (render-blocking interacts with the R45c black-frame fix). Find out with `git log -S` whether
      it was removed on purpose; then make the comment match what the file does, and say in the notes what you found.
