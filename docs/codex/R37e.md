## Goal (what Anh should SEE)
Click a Work main image: the card puffs, grows, reaches full screen, bends inward and keeps slowly zooming in while the project page
appears, and the zoom settles once, on the project page, into the header exactly as it rests today. No stop, no hold, no turning point.
Back: the reverse, also without a stop. Hovering an image never hitches.

## Why (R37d findings)
- A zoom pulse that returns to 1 must pass through zero speed at its turning point: that dip cannot be tuned away. The reference never
  turns back: it keeps zooming. So the zoom must be MONOTONIC (one direction only) and may only settle at the very end.
- The ~270 ms hold before the project header is the next page loading; the Work page alone cannot hide it.
- Hover prepare hitched 41-47 ms at 4x CPU throttle (real-speed cost not measured).
- Cowork's 15 % dip rule was too strict: the reference video itself fails it (30 duplicate frames). Judge against the reference's
  own curve (AGENTS.md section 7).

## Design (one motion split across two pages by WALL-CLOCK time)
1. One shared, time-based curve for the content zoom, defined in ONE module imported by both sides (e.g. src/effects/flight-curve.js)
   and inlined in the project pages' head script (or kept tiny enough to duplicate verbatim; then add a test that both copies give the
   same values). Inputs: t0 (Date.now() at the click, wall clock, so it survives the page change), durations, start / end zoom.
2. Zoom direction: the content zooms IN monotonically and ends EXACTLY at the project header's own start pose (scale 1 relative to the
   header crop at scroll 0). So the content must start slightly zoomed OUT (start zoom zStart < 1, e.g. 0.97, fit by eye) when the
   card reaches full screen, then ease monotonically to 1 with a single smooth settle (no overshoot, zero speed only at the end).
   Total zoom tail ~0.5-0.7 s after full screen (fit to the reference's long settle; Anh tunes).
3. The inward bend (lens) stays on the Work page: it rises from the landing speed (R37d carry), peaks, and returns to 0 BEFORE
   navigation (the lens returning to 0 is fine: the zoom keeps the motion alive while it does). Navigation starts as soon as the lens is
   under 1 device px at the edges; the zoom is still moving at that moment ON PURPOSE.
4. While the browser fetches the next page, the Work page keeps drawing the zoom from the wall-clock curve (the old page stays painted
   until the new one commits), until pagehide.
5. Project page (all 7 work/*.html heads + src/project.js): the inline hand-off script already paints the #pxt overlay image. Extend it:
   if the `pxt` record has a `flight` field (t0, curve params), set the overlay image's transform from the SAME curve at the current
   Date.now() on its first paint and every frame (a tiny rAF loop in the inline script, transform only), until the curve ends. Remove
   the overlay as today only when BOTH the curve has ended and the header image is decoded (if decode is late, the overlay simply sits
   at the end pose: the motion has already settled, nothing pops). Without a `flight` field (homepage frame open, old records) the
   overlay behaves exactly as today.
6. HAND-OFF BUG to fix at the same time (found by Cowork, it breaks the transition on Cloudflare Pages): the head script returns early
   with `location.pathname.indexOf('/' + d.slug + '.html') < 0`. Cloudflare Pages redirects /work/duhat.html to /work/duhat (no .html),
   so on the hosted preview the overlay is never painted. Accept both forms (path ends with '/' + slug or '/' + slug + '.html',
   optional trailing slash). Check the same pattern in work/index.html (#pxb) and anywhere else a path is compared.
7. Way back (playBack): reverse with continuous speed: at full screen the content zoom eases monotonically from 1 to the zStart pose
   while the inward bend rises and falls, and the shrink starts carrying that motion (no stop at full screen, no zoom turning point).
   The project page side of the back path (pagehide record) stays as it is.
8. Hover hitch: prepare the GL renderer for the CENTRED image during idle after the Work page loads (requestIdleCallback with a
   timeout, after the strip has settled), and re-prepare on idle when the centred project changes; hover of another image prepares
   that one (still one prepared renderer max). Upload a texture sized for the full screen at the device pixel ratio cap (createImageBitmap
   with resizeWidth / resizeHeight from the decoded image, not the 4K source), sliced as in R37d; the sharper header file swap stays.
   Measure hover / idle prepare cost at REAL speed and at 4x throttle; target: no frame over ~20 ms at real speed while hovering,
   scrolling or idling; report the 4x numbers too.
9. ?tune: zStart, zoom tail duration, lens carry / strength / timing, back zoom; descriptions; Copy values. Remove keys that no longer
   apply (R37c zoom pulse / reboundZoom if replaced).

## Assumptions and likely misreadings
- A1. The zoom is MONOTONIC: in on the way in, out on the way back. The bend may rise and fall; the zoom may not turn around.
- A2. Wall clock (Date.now()) is the shared time base across pages; performance.now() resets on a new page.
- A3. Option B touches all 7 project page heads and src/project.js; the homepage path must stay byte-for-byte equivalent in behaviour.
- A4. zStart < 1 means the card arrives very slightly zoomed out and then zooms in; it must not look like a jump when the card
  reaches full screen: blend the zoom in from the growth (the growth itself already scales the picture).
- A5. The .html fix (step 6) matters even if Anh never notices it locally: localhost keeps .html, the hosted preview does not.
