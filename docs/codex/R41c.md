## Evidence (Cowork, from Anh's recording; files in docs/reference/)
Recording: `r41b-iphone-2026-10-31.mp4` (iPhone, 1290x2796 original, 120 Hz ProMotion screen, recorded at 60 fps; re-encoded 430 wide with the original frame timing). Times below are in that file.
- STALLS while flicking (frozen frames between moving frames, measured by frame-to-frame difference): 0.95 s (11 frames, ~180 ms), 2.10 s (5), 3.00 s (5), 4.21 s (11, ~180 ms), 8.77 s (6), 9.96 s (8), 12.63 s (7). After each freeze the strip JUMPS ahead (catches up), which Anh feels as stutter and as the strip "pulling the project back to centre".
- The stalls line up with the TITLE: `r41b-iphone-stall-title-sheet.png` (0.80-1.37 s, 30 fps): the strip starts moving, "Nam Long" fades on the picture, then for ~170 ms the screen is frozen with the title drawn as GREY TEXT BELOW the picture (detached from it), then the strip jumps a whole project. The same pattern at 4.21 s (the counter changes project mid-flick, freeze ~200 ms, jump of 2 projects). So the lite title's leave / enter work blocks the main thread on iOS and the leave state is drawn in the wrong place.
- NO OPEN TRANSITION: `r41b-iphone-tap-plain-sheet.png` (16.3-18.6 s): after the tap the address bar shows a loading X, the screen is black for ~0.3 s, then the project page appears full screen with no flight: the PLAIN NAVIGATION fallback ran (a full page load). Back (iOS swipe-back) lands on the right project (Similac), also without animation.
  Likely reasons, in order (confirm, do not assume): (a) the frame-time guard tripped during the stalls (`guard.state.warp` false -> tap gate "degraded" -> plain); (b) `weakDevice()` (src/util/device.js) failed to recognise the Apple GPU on this iOS version (renderer string masked) and the cores test fired; (c) another gate (reduced motion, Save-Data, WebGL2 missing, the gesture-intent gate). Note: the transition must not be quietly disabled by the stalls this request is fixing.
