## Rules (Anh, 2026-11-01)
1. STACK BY DEFAULT: one item per row, full width (16 px gutters for text; media edge to edge unless the item is small on desktop, then keep a margin, report the threshold).
2. SWIPE ONLY FOR SETS: a sideways swipe row only for 3 or more items of the SAME aspect ratio (within ~10 %) that are meant to be browsed (post grids, storyboard frames, film stills). Pairs and mixed shapes stack. The swipe row keeps the next item peeking and a small count ("1 / 6") under it.
3. COMPOSITIONS KEPT: a desktop `stage` (free layout) becomes ONE phone composition per block, not a list: keep the relative placement and overlaps, scaled to the phone width, with the block height following the content (no tiny text: text items inside a stage are lifted out and placed right after the composition at the readable size). If a stage is too wide to read at phone size, split it into two compositions stacked. Show Anh the result for each stage; he may want some flattened.
4. SCROLL EFFECTS TRANSLATED (not dropped; reduced motion = no motion, final state):
   - letter fade (desktop text blocks) -> line-by-line reveal on enter (lines rise ~8 px and fade in, ~60 ms stagger, done in ~0.6 s);
   - parallax masks -> mask reveal on enter (the picture opens from the centre in its frame, slight scale 1.06 -> 1 over ~0.8 s);
   - pinned side-scroller (`scroller`) -> a swipe row if its items are a set (rule 2), otherwise a stack;
   - growing strip (`grow`, Similac) -> full-width picture that scales in from the strip height on enter;
   - time-based only (AGENTS.md 7), run once per block, no scroll-linked work on the phone.
5. HERO: when the desktop hero has text in the picture or is landscape on a tall screen, use a phone crop: `hero.phone` in data.json (a ref or a focal point `{ x, y }`); default focal point centre-top for posters. Bitis needs one (title fully visible). The resting zoom (FLIGHT.zEnd) and the open / back transition must land on the same crop.
6. Desktop must not change.
