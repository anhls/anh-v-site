# R42b: back from a project opened mid-scroll lands exactly on its card (no cross-fade)

Side: desktop (shared router; phone/tablet must not break) · Folder: D:\Portfolio website\anh-v-site · Branch: claude/r42-same-page-nav (continue R42)

Planner: Cowork, 2026-10-11. Builder: Claude Code (built R42). AGENTS.md applies (section 12: write the busy note first). This brief wins over docs/requests.md.

## Goal (what Anh should SEE)
Back always ends with the bending card shrinking straight into its card in the Work strip, with no fade or double image, whether
the project was opened from a resting strip or while the strip was still scrolling / snapping.

## The bug (from Anh's recording 2026-10-11 23:17, 60 fps, frame analysis by Cowork)
- Project 1 opened from a resting strip: back is fine.
- Project 3 (Sulwhasoo) opened mid-scroll: back shrinks with the bend from 0.47 to 0.70 s, then for about 3 frames (0.70 to 0.77 s)
  the flying card is bigger and offset from the real card, both are visible on top of each other, then it fades across.
- Likely cause: the flight aims at the centred resting rect while the strip resumes at the saved mid-scroll position (or the
  reverse), and a cross-fade hides the mismatch. Confirm in code before fixing.

## Fix (decided with Anh: snap to rest)
1. At the start of back, while the full-screen header still covers everything, put the strip at its FINAL RESTING position for
   that project (the snapped place it would settle to anyway). Not the raw mid-scroll value. Any running snap / inertia is ended.
2. Read the real card's rect there once (after layout, before the first flight frame) and use it as the flight target.
3. Remove the cross-fade. With matching rects the last flight frame hands over to the real card with a direct swap.
4. Keep everything that R42 got right: puff, bend, rounded corners, same project, clicking again always animates, first frame
   after the trigger under 20 ms (do the measuring work so it fits, or before the trigger).
