### 4.2 R37 traps
- 4.2.1 `TRANSITION.sec` IS SHARED WITH THE HOMEPAGE. The homepage frame open (`initFrameOpen` in `src/effects/project-transition.js`) uses the
  same `runProjectTransition` and the same `TRANSITION.sec` / `fadeSec`. The request text says "TRANSITION.sec 0.9 -> 0.4", but doing exactly that
  would also speed up the parked homepage.
  -> Add Work-only values (e.g. `TRANSITION.work = { sec: 0.4, pushSec: 0.4, ease: 'expoOut', bulgeAmp, bulgePeakAt, bulgeOvershoot }` or flat keys
  `workSec` etc.) and use them only on the Work path (the call in `src/work.js` and `playBack`). The homepage path keeps `TRANSITION.sec 0.9`
  exactly. Verify the homepage open is unchanged (same frames before / after at 3 points of its move).
- 4.2.2 There is no "expo" in the site's ease file. `src/util/ease.js` `EASES` has only `circ`, `sine`, `quad`, `cubic` (all in-out). The request
  says "the site's expo out": that was a planner mistake.
  -> Add `expoOut: (t) => (t >= 1 ? 1 : 1 - Math.pow(2, -10 * t))` to `EASES` (exact 1 at the end; tiny jump at t=1 of 2^-10 is fine because you
  clamp), or use GSAP's `expo.out`. An OUT ease (fast start, slow end) is what the reference shows; today's `circ` is IN-OUT (slow start).
- 4.2.3 The bulge formula in requests.md is ambiguous. "x moves away from the box centre by amp * (1 - (2v - 1)^2)" could be read as moving
  the whole picture. What is meant (with u, v in 0..1 across the box, s = the box's shorter side in px, A = bulgeAmp * bump(t)):
      dx = (2u - 1) * A * s * (1 - (2v - 1)^2) / 2
      dy = (2v - 1) * A * s * (1 - (2u - 1)^2) / 2
  i.e. 0 at the centre and at the four corners, maximal at the middle of each edge, the edges bow OUTWARD (a pillow / barrel, never pinched
  inward). Use texture coordinates of the undistorted quad (the picture is carried with the mesh, like a printed sheet being inflated), not a
  lens that magnifies the middle.
- 4.2.4 "Peak at 0.5" means of the MOVE'S TIME, and the bump must be exactly 0 at t = 0 and t = 1 with zero slope at both ends (use e.g.
  sin^2 over a remapped t so the peak sits at bulgePeakAt). The image MUST land exactly flat; a leftover 0.001 is a visible seam at the hand-off.
- 4.2.5 Overshoot = the BOX SIZE passes the full screen and comes back, not the bulge. Use `withOvershoot(ease, amount, window)` from
  `src/util/overshoot.js` on the size/position progress; its base ease must end with zero slope (expoOut nearly does; check the end is exactly 1).
  The final frame is exactly 0, 0, innerWidth, innerHeight.
- 4.2.6 Object-fit cover crop changes during the move. Today's DOM path grows an `<img>` with `object-fit: cover`, so the crop changes as the box
  goes from the image's slot aspect to the screen aspect. The GL quad must compute the SAME cover crop for each frame's box (uv scale / offset from
  the image's natural size vs the box size), or the picture will visibly slide at the hand-off.
- 4.2.7 Which picture to upload. Start texture = the already decoded `<img>` the Work page shows (`it.img`, passed as `startSrc`). The full header
  file loads in the background (`preloadHeader`, a `srcset` image): when it is ready, re-upload (same picture, sharper). Do not wait for it to start.
  Same-origin files, no CORS issue. Upload with `UNPACK_PREMULTIPLY_ALPHA_WEBGL = false` for these opaque JPG/WebP pictures, `LINEAR` filtering,
  generate mipmaps or the small start frame will shimmer; clamp to edge.
- 4.2.8 Canvas size and DPR. A full-viewport canvas at devicePixelRatio (Anh's 4K screen can be DPR 1 at 3840 or DPR 2 at 1920): cap the backing
  store the same way the other site canvases do (look at `src/effects/frame-gl.js` / `src/util/dpr.js` and copy their cap). The overshoot makes the
  quad slightly larger than the screen: that is fine, it is clipped by the canvas.
- 4.2.9 Stacking. The overlay root `.px` is `position: fixed; z-index: 8`; inside it `.px__bg` (black layer, opacity `blackMax` = 0 on the Work
  path), then `.px__box` with the image(s). The project name element is lifted to z-index 9 (stays above). Put the GL canvas inside `.px`
  above `.px__bg` and in place of `.px__box` while it draws; keep `.px__box` in the DOM with `visibility: hidden`, show it and remove the canvas
  on the final frame BEFORE `location.href` changes (the project page's first paint reads `sessionStorage.pxt` and paints the DOM overlay; that
  hand-off must stay exactly as it is).
- 4.2.10 The way back is a DIFFERENT code path. `playBack()` (same file) runs on the Work page after arriving from a project page. The Work
  page's inline script in `work/index.html` paints `#pxb` (a DOM overlay at the header's last box) in the first frame from `sessionStorage.pxb`;
  `playBack` then shrinks it to the centred image's box and hands over to the Work page's own WebGL canvas two frames after the end (`tailEnd`).
  The START box is the header where it was when the visitor left the project page: often full screen, but it can be partly scrolled up
  (`rec.leave.sec` / `rec.leave.img`). So on the way back: the first frame is the DOM `#pxb` (no GL yet), GL takes over once its texture is
  ready (same picture, no pop), the bulge bump runs over the shrink, and at the end the GL canvas must disappear on the same frame the Work page's
  own image shows (keep the two-frame rule). `playBack` ends early on wheel / key / pointer (`stop()` jumps the timeline to 1): the GL path must
  survive a jump to the end (flat, then removed).
- 4.2.11 Push off screen is ALREADY BUILT (R30, `TRANSITION.pushClear: 1`, `prepareClear`, `TC` in `src/work.js`). Anh's "pushed off screen"
  means: keep it. Only its timing changes with the faster move (`pushSec` for the Work path = the new move time; re-tune `clearStagger` so far
  cards do not trail behind). Do not rewrite the push.
- 4.2.12 Hover growth. In v2 the centre image grows a little on hover (`gl.hs`, R33 `hoverScale`); the click reads the UNSCALED frame on purpose
  (`sc = ui ? 1 : ...`). Keep that: the GL quad starts from the rect the call already computes.
- 4.2.13 Only one transition at a time (`running` flag). Keep it; a second click during the move does nothing.
- 4.2.14 Fallbacks must not regress. `transitionOK()` already turns the transition off for reduced motion, `?gl=0` and tall mode (unless
  `TALL.transition`). Add: WebGL2 unavailable or the context lost during the move -> finish the move with today's flat DOM path (no error, no
  frozen frame). Tall / phone mode, if `TALL.transition` is on, keeps the flat DOM path (no bulge) in this request.
- 4.2.15 No `?leakcheck` exists yet (it is planned in R24c, not built). The "no GL context left after 20 cycles" check must be done by your own
  script: count canvases in the DOM, wrap `getContext` to count live contexts, call `WEBGL_lose_context.loseContext()` on dispose, and watch
  `performance.memory` if available. Browsers limit live WebGL contexts (about 16): a leak shows up as old contexts being dropped.
- 4.2.16 "Reference frames" for the contact sheet: you may not be able to download the Dribbble mp4. If you can (the mp4 URL is
  https://cdn.dribbble.com/userupload/29337673/file/large-282f7e13fc3bfee6978d72e0d8c17f46.mp4), save it to `docs/reference/r37-dribbble.mp4` and
  extract frames 5.80-6.25 s with ffmpeg-static. If you cannot, make the contact sheet of ours only and say so; Anh compares by eye.
- 4.2.17 "Pixel-identical at rest" = with no transition running the Work page must render exactly as before (0 px diff at the same scroll / drag
  state). The new code must not create any canvas or GL context until a click.
