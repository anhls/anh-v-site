# R37b build brief (Codex or any agent): make the Work open / close match the reference

Written by Cowork (Claude, the planner) on 2026-10-11 for Anh, after Anh judged the R37 build: "the effect is not like the reference".
Read docs/codex/R37-R38.md sections 1-3 (project, commands, house rules) if you have not; they still apply. This file wins over
docs/requests.md for R37b.

## 0. Why R37b exists (the planner's mistakes, not the builder's)
R37 was built exactly as specified. The spec was wrong in three places, which is why it does not look like the reference:
1. Ease: the spec said expo OUT. It reaches ~90 % of full screen after 0.1 s of a 0.4 s move, so the card "pops" and then sits still
   for 0.25 s (see tools/scratch/r37-shots/actual-1920-open-sheet.png: frames 3-10 are identical).
2. Bulge timing: the bump peaks at 0.5 of the TIME. Because of (1) the card already fills the screen by then, so the bulge happens
   mostly outside the viewport and is never seen.
3. Bulge size: the formula divided by 2 and the start value 0.06 was low, so the edges bow by ~3 % of the short side. The reference
   bows visibly, roughly 12-15 %.
Also missing: the reference card ROUNDS ITS CORNERS while it inflates (an old-TV-screen shape), and the picture inside looks slightly
magnified. Ours keeps sharp corners.
What R37 got right and must be kept: the transition-only WebGL renderer (src/effects/bulge-gl.js), the clearing push, the GL -> DOM
hand-off overlap, the fallbacks (?gl=0, reduced motion, context loss, tall mode), the cleanup, the Work-only values (homepage untouched).

## 2. Changes (all in the existing files: src/effects/bulge-gl.js, src/effects/project-transition.js, src/timeline.js, src/util/ease.js, src/work/tune.js, src/effects/tune-docs.js)
1. Size curve (Work path, open and back): base = cubic in-out over the first `TRANSITION.workLandAt` (start 0.7) of the move, holding
   at 1 after that; overshoot = `withOvershoot(base, bulgeOvershoot, bulgeWindow)` so the box passes full screen by ~3 % once (around
   t ~ 0.8) and is exactly flat and full at t = 1. Note: `withOvershoot` needs a base that ends with zero slope: the held cubic does.
   Add `cubicInOut`-held helper in ease.js if useful; keep `expoOut` (other code may use it later) but the Work move must not use it.
   Fit `workSec`, `workLandAt`, `bulgeOvershoot` to the measured reference curve (box width per frame). Report both curves.
2. Bulge timing: replace the whole-move bump with one that starts at t = 0, peaks at `bulgePeakAt` (start 0.25) and is EXACTLY 0 from
   `bulgeEndAt` (new, start 0.7) to 1, zero slope at both ends (e.g. sin^2 on the remapped time). The card must be flat before it
   overshoots and lands.
3. Bulge size: in the vertex shader remove the `/ 2.` so the middle of each edge moves outward by `bulge * min(box.z, box.w)`.
   `bulgeAmp` start 0.13 (fit to the reference). Formula otherwise unchanged (centre and corners fixed, edges bow outward):
   p += q * (1 - q.yx * q.yx) * bulge * min(box.z, box.w).
4. Rounded corners (new): in the fragment shader, pass the undistorted box coordinate (uv) and mask to a rounded rectangle in box
   pixels: radius = `cornerAmp` (start 0.08) * min(box.w, box.h) * the same bump. Anti-alias over ~1 device px (smoothstep on the
   signed distance), alpha 0 outside (premultiply correctly: the canvas uses premultipliedAlpha false, so output color.rgb with alpha,
   and check the edge has no dark fringe). Radius 0 at the end, so the hand-off frame is unchanged.
5. Magnify (new, optional): sample the texture zoomed toward the box centre by `zoomAmp` (start 0.04) * bump. If it does not read like
   the reference, set the default to 0 and say so.
6. Push: `workPushSec` = the landing time (about workSec * workLandAt, ~0.28 s) so the neighbours are gone when the card lands.
7. Way back (`playBack`): the same curves, time-reversed (the card bulges and rounds during the shrink and is flat before it lands in
   its slot). Compare with the reference close frames.
8. ?tune: add `workLandAt`, `bulgeEndAt`, `cornerAmp`, `zoomAmp` to the TRANS list in src/work/tune.js with descriptions in
   tune-docs.js; all in Copy values. Update the existing slider ranges if the new defaults fall outside (bulgeAmp max 0.3 -> 0.4).

## 3. Assumptions and likely misreadings
- A1. The planner's numbers (0.7, 0.25, 0.13, 0.08, 0.04, 3 %) are estimates from single frames. Measure and fit; report final values.
- A2. "Bulge" = the SHAPE of the card (edges bow out, corners round). "Overshoot" = the card's SIZE passing full screen. They are separate
  and happen at different times: bulge early, overshoot late. Do not let the bulge run into the overshoot.
- A3. The rounded corners are a mask, not a mesh change. Do not move the mesh corners.
- A4. Bulge amount is relative to the box's CURRENT short side (it grows with the card), not the screen.
- A5. The reference card starts from a slider that is already bent; our Work strip has its own warp. Do not add a pre-click bend.
- A6. The homepage frame open uses `TRANSITION.sec` / `circ` and must stay exactly as it is (re-run the 3-point homepage identity).
- A7. R38 (light theme) is done on this branch: the GL canvas clears transparent; check the rounded corners look right on BOTH themes
  (the page colour shows outside the mask; in light mode that is #ece9e2).
- A8. Anh judges by eye. If your fitted numbers look worse than the planner's, keep the better-looking set and explain.
