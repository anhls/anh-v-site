## Goal (what Anh should SEE)
Desktop, then phone / tablet: click a Work image -> the card puffs, grows, lands and keeps zooming into the project header with NO hold,
snap or flash at any point (there is no page load any more). Back (browser back button, mouse back, Alt+Left, iOS swipe-back, Android
back, the site's own back link) -> the header shrinks back WITH the bend into the same project's slot on the still-alive Work page, at the
exact place the visitor left. Clicking again immediately works every time.

## Why (evidence)
Anh's recordings (21:31, 22:20): ~90-100 ms freezes at every page change, no bend on the way back, and a second click after back plays no
animation. R37-R37f measured the same: the Work page and the project page are separate documents; the switch between documents (and the
Work page being rebuilt on return) cannot be animated through. Codex hit this limit three times (docs/codex/R37f-notes.md). Removing the
document switch removes the cause.

## Design
1. A small client-side router (e.g. src/router/ or src/effects/page-swap.js; SHARED in docs/OWNERS.md) used by the Work page only:
   - Open: on a main-image click (desktop) / accepted tap (lite, R41 tap gate in mode-lite.js), start the existing flight
     (runProjectTransition) and, in parallel, build the project page into a new container in the SAME document from data.json with the
     existing builders (src/project/desktop.js + src/sections/project-page.js on desktop; src/sections/project-page-tall.js in tall
     mode), hidden under the flight. history.pushState({ project: slug, workPlace }, '', '/work/<slug>.html'). When the flight ends the
     project container is shown, the flight canvas removed; there is no navigation.
   - While a project is open the Work page is PAUSED, not destroyed: its rAF tick, Lenis, listeners (wheel / pointer / keys / resize
     handled via a pause flag or AbortController per phase), and GL draws stop; its canvases stay allocated (so the way back needs no
     setup: that is what gives the reverse bend for free); its DOM is hidden (visibility / inert / aria-hidden), not removed.
   - Back: on popstate (and the site's own back control, which calls history.back()), run the reverse flight (playBack) from the project
     header's CURRENT position (it may be scrolled) into the live Work slot of the same project, WITH the bend; tear the project
     container down completely (its Lenis, ScrollTriggers, observers, listeners, videos, GL if any, DOM); resume the Work page exactly where
     it was. Forward after back (popstate to a project URL) opens it again (with or without the flight).
   - Document state on swap: title, meta description / canonical / og (from the project data, as the static page has), html classes /
     data attributes the project CSS needs, focus to the project's main heading (accessibility), scroll position of the project page starts at
     the top, the nav / wordmark state as on the static page, the theme (R38) untouched.
   - CSS: the project page styles (project.css / tall-project.css) must be loaded on the Work page lazily (dynamic import of the project
     module graph on first prepare / idle, so the Work page's first load is not slower) and must not leak into the Work page while it is
     visible (scope under the project container or a root class).
2. Direct visits, reloads, shared links, search engines: the static work/<slug>.html pages stay exactly as today. Reloading while a
   project is open loads the static page (correct URL).
3. Fallbacks: reduced motion, ?gl=0, WebGL context lost, weak devices (R41 policy), or any error in the swap -> today's plain navigation
   (location.href). The swap path must never leave a half state: on any exception, navigate normally.
4. Homepage frame open (index.html -> project) stays a normal cross-document navigation for now (the homepage is parked; it already lands
   on the zoomed header via R37f's tail). Project -> another project (More Projects links) stays a normal navigation in R42.
5. Lite (phone / tablet): wire the same router, but keep TRANSITION_POLICY_LITE.enabled false in R42 (R41 Part B switches the effect on);
   the BACK-TO-SAME-PROJECT part (R41 B1) is solved by R42 for lite too: with enabled false, a tap still swaps in place without the flight
   (instant), and back returns to the same project. Reconcile TRANSITION_POLICY and TRANSITION_POLICY_LITE in settings/tall.js into one.
6. Remove what becomes dead code only where it is clearly unused by the remaining paths (the sessionStorage hand-off stays for the homepage
   path and fallbacks).

## Assumptions and likely misreadings
- A1. The URL must still change to /work/<slug>.html so sharing and reload work; this is not a hash router.
- A2. "Paused, not destroyed" is the point: do not rebuild the Work page on back.
- A3. The project page built in place must look identical to the static page (same builders, same CSS); check it pixel by pixel.
- A4. Memory: one project open at a time; the project container is fully torn down on back.
- A5. If a builder assumes it owns the whole document (e.g. querySelector on document, global Lenis, window scroll), adapt it to a
  root element; note every such change.
- A6. This replaces the cross-document parts of R25/R28/R37e/R37f for the Work page only.
