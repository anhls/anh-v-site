# R39: hosted previews on Cloudflare Pages (no PC needed to look at a build)

Planner: Cowork (Claude), 2026-10-11. Builder: any agent. AGENTS.md applies (read it first). This brief wins over docs/requests.md.

## Goal (what Anh should SEE)
Every push to GitHub builds the site in the cloud, and each branch has its own private link (e.g. codex-r37-r38.anh-v-site.pages.dev)
that Anh opens on his phone or laptop, with no PC on. Nothing is public until launch.

## How it is set up (decided by Cowork + Anh; split between Anh's clicks and repo work)
- Host: Cloudflare Pages (free), connected to the private GitHub repo anhls/anh-v-site.
- PRODUCTION branch = `live`. Cowork created `live` on GitHub as a placeholder with only a README (no package.json), so its build fails
  and the public `anh-v-site.pages.dev` address shows NOTHING until launch. This is on purpose: the repo holds unreleased client
  material (Duhat / Vingroup, Nam Long pitch work). Do not "fix" the failing production build.
- Every other branch (work-v2, codex/*) deploys as a PREVIEW at `<branch>.anh-v-site.pages.dev` (branch name lowercased, `/` -> `-`).
  Previews are protected with Cloudflare Access (only Anh's Cloudflare login can open them) and carry `X-Robots-Tag: noindex` by default.
- At launch (a later request): put the approved site on `live`, attach the domain anh-v.com (bought at PA Vietnam), remove the placeholder.

## Part A: Anh's clicks (Cowork walks him through; the builder does NOT do these)
1. Cloudflare account (free) -> Workers & Pages -> Create -> Pages -> Connect to Git -> GitHub -> authorise ONLY the repo anhls/anh-v-site.
2. Project name `anh-v-site`. Production branch: `live`. Framework preset: none / Vite. Build command: `npm run build`. Output: `dist`.
   Root directory: (empty). Environment variable: `NODE_VERSION` = `22` (also set by .nvmrc from Part B).
3. Settings -> General -> Enable access policy (preview protection). Settings -> Builds -> Branch control: preview branches = all
   (or include `work-v2` and `codex/*` only, to save builds: the free plan has 500 builds a month and one at a time).
4. Open the preview link of `codex/r37-r38` on the phone, log in, check the Work page and one project.

## Part B: repo work (the builder)
Branch: the current working branch the brief owner names (default: codex/r37-r38 after R37c is done). Files: `.nvmrc`, `public/_headers`,
`docs/HOSTING.md`; anything else only after asking.
1. `.nvmrc` with `22` (Cloudflare's build image default is 22.16; local dev uses whatever Anh has: note his version in HOSTING.md).
2. `public/_headers` (Vite copies public/ into dist/ as-is): long cache for hashed files: `/assets/*` -> `Cache-Control: public,
   max-age=31536000, immutable`; media in `/media/*` and `/fonts/*` -> `public, max-age=2592000` (30 days; they are not hashed, so not
   immutable); HTML stays default (revalidated). No security headers that could break WebGL / video (no strict CSP in this request).
3. Clean URLs: Cloudflare Pages serves `/work/duhat.html` by redirecting (308) to `/work/duhat`. The site links and navigates to
   `/work/<slug>.html` (hero.js, project-index.js, more-projects.js, selected-work.js, work.js, project-transition.js) and the
   homepage frame reads the slug with the regex `work\/([^/.]+)\.html` from a link's href (not from the page URL, so it still works).
   For R39: KEEP the .html links (one cheap redirect). Verify on the preview that: the R25 / R28 / R37 transitions still hand off
   (sessionStorage survives a same-origin redirect), the back transition still works, canonical / sitemap URLs: list any that disagree
   with the final URL for the launch request; do not change them now.
4. 404: Pages serves `dist/404.html` for unknown paths when it exists (it does). Verify `/nope` shows our 404 with status 404.
5. Install in the cloud: `npm ci` runs on Cloudflare. Watch the build log for `ffmpeg-static` (downloads a large binary at install)
   and `sharp` (native binary). If either fails or adds minutes, REPORT it with the log lines and a proposal (e.g. moving ffmpeg-static
   to optionalDependencies); do not change package.json without Anh's OK (AGENTS.md section 4).
6. Build size: Pages limits are 20,000 files and 25 MiB per file. Report the dist file count and the largest file.
7. docs/HOSTING.md (plain words for Anh): what the links are, how to open a preview, what `live` is for, the build limits, how to
   redeploy, how to roll back (Cloudflare keeps every deployment: Deployments -> a previous one -> Rollback), and what launch will need.
