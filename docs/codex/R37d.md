# R37d: Work open / close as ONE continuous motion (no stop between landing and rebound, no click hitch)

Planner: Cowork (Claude), 2026-10-11, from Anh's screen recording of the R37c build (desktop, 3840x2160, 60 fps). Builder: any agent.
AGENTS.md applies (read it first). This brief wins over docs/requests.md. Context: docs/codex/R37b.md, docs/codex/R37c.md (+ notes).
Order: R37d first, then R39 (hosting). Push after every commit as usual (pushes only build a private preview).

## Goal (what Anh should SEE)
Click -> the card puffs, grows, hits full screen and carries straight on into the inward rebound, then settles once, in one
unbroken gesture like the reference. No moment where everything stands still before the project page takes over. No hitch at the click.

## What is wrong now (Cowork's measurement of Anh's recording)
Per-frame motion = mean absolute difference between consecutive frames (greyscale, 480 px wide). Click at about 4.30-4.43 s:
| Time (s) | Motion | What happens |
| 4.40-4.42 | 0.00 (2 identical frames) | HITCH right after the click: nothing updates (GL setup on click; R37 notes: first frame ~125-139 ms) |
| 4.43-4.87 | 2-8 | the move: card grows and lands (good) |
| 4.87-4.93 | 0.0-0.7 | DEAD STOP: the move has eased to zero speed, everything waits |
| 4.93-5.28 | 0.6-3.9 | the rebound starts again FROM REST |
| 5.30-5.45 | ~0.0 | SECOND STOP: ~150 ms still before the project page shows |
| 5.47 -> | 3-5 | the project page's own intro (wordmark etc.) |
Cause: the move (held cubic + size overshoot + settle) and the rebound (its own lobe) are two animations placed end to end. The move
decelerates to zero velocity, then the rebound accelerates from zero: stop-then-go. In the reference the card reaches full screen
STILL MOVING and that momentum becomes the inward bend; motion never drops to zero until the final settle.

## Steps
1. One continuous motion (Work open):
   - The size curve reaches full screen at `workLandAt` WITH non-zero speed (do not ease to zero at the landing).
   - At that moment the content rebound starts, its initial speed taken from the landing speed (continuous velocity: no kink, no stop).
     Model it as one damped spring / one continuous curve for "size + rebound": grow -> pass into the inward bend -> settle once, to
     exactly flat, zero speed only at the very end.
   - Remove the separate box size overshoot and its settle window (`bulgeOvershoot`, `bulgeWindow`) for the Work path: the rebound IS
     the overshoot now (the size overshoot was hidden by the screen edges anyway). Keep the keys only if other code needs them.
   - Keep R37b/R37c's look as the starting point: workSec 0.6, bulge 0.13 peak 0.25 end 0.7, corners 0.08, rebound strength ~0.6 x
     bulge, zoom pulse 0.025 returning to 1. Re-fit by eye / sheet if continuity changes how strong they read.
2. No click hitch: prepare the GL renderer on HOVER. On pointerenter of a main image (where preloadHeader already runs): create the
   context, compile the program, build the mesh, upload the already decoded image texture (and generate mipmaps), keep it hidden.
   The click only starts the animation with the ready renderer (create on click stays as the fallback). Dispose the prepared renderer
   on pointerleave after ~2 s, on a different image's hover, on scroll/drag start, or on page hide. Never keep more than ONE prepared
   renderer. Touch / tall mode: unchanged (no hover).
3. The wait before the project page (5.30-5.45 s): measure, from the end of the rebound to the project page's first frame showing the
   header, the real gap (Performance marks exist: pm('fwd:end') etc.). Then:
   a) if > ~100 ms: let the last part of the rebound's settle (the small tail) run until navigation instead of ending early, so motion
      fades out rather than freezing; navigation still starts when the image is flat enough for an invisible hand-off (define "flat
      enough" as the remaining lens/zoom under 1 device px of displacement at the edges);
   b) if the gap is still visible after (a): do NOT build it, REPORT option B for Anh: the project page plays the end of the rebound
      itself from the sessionStorage hand-off (bigger change).
4. Way back (playBack): the same continuity in reverse: the inward rebound at full screen flows straight into the shrink (the shrink
   starts with the rebound's speed, no stop between them), then the card lands in its slot once.
5. ?tune: update the TRANS list for any new / removed keys (e.g. a spring stiffness / damping or a "carry" amount for how much landing
   speed feeds the rebound), descriptions in tune-docs.js, Copy values.

## Assumptions and likely misreadings
- A1. "Continuous" means continuous SPEED, not just continuous position: a curve that reaches the target and then starts a new lobe is
  exactly the bug. Check the velocity at the joint (should be the same on both sides, not zero).
- A2. The size overshoot is removed on purpose; do not reintroduce a settle before the rebound.
- A3. The 150 ms hold may be page load, not animation. Measure before changing anything there; option B is Anh's decision.
- A4. Hover prepare must never run on touch devices or in tall mode, and must never keep two GL contexts alive.
- A5. Anh judges by eye; the motion curve is a guard against stop-then-go, not a target to copy number for number.
