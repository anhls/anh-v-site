## Goal (what Anh should SEE, desktop)
Click a Work image: one continuous motion (puff, grow, land, the picture keeps zooming IN and settles once) with no black frame at the
page change, no visible stall, no doubled image at the edges. Back: smooth, no stalls while the Work page loads.

## Evidence (Cowork's frame analysis of Anh's recording, 3840x2160 @ 60 fps of a 144 Hz screen)
1. FLASH: on the second open (Forbes) the screen is fully BLACK for 2 frames at the page change, then the picture returns. Plus ~0.3 s
   near-still around the switch.
2. STALLS: on the way back, when the Work page starts loading, motion freezes 100-130 ms, then jumps in large steps (dropped frames:
   the Work page's start-up work runs during the animation). The open's push-away shows uneven frame pacing.
3. GHOST: during the settle the left edge shows the plant / vase TWICE, offset: R37e zooms the picture in from 0.90, which does not
   cover the screen, and fills the gap with a second resting copy under a feathered edge. That second copy is the ghost.

## Decisions (Anh)
- Keep the zoom-IN look of the reference: the zoom moves only inward, from 1.0 when the card reaches full screen to zEnd > 1.
- The project header's resting state BECOMES the zoomed-in picture (no need to keep the original crop): the header image rests at
  scale zEnd (start ~1.10, tune by eye against the reference). The transition ends exactly on that rest state, so the hand-off is an
  identical frame (no crossfade, no underlay, no ghost). Picture scale is always >= 1: it always covers the screen.

## Steps
1. Shared value: add `export const FLIGHT = { zEnd: 1.10 }` to src/settings/shared.js (exactly this line; R41 may add the identical
   line on its branch, identical lines merge cleanly). The flight curve's zoom goes 1.0 -> zEnd, monotonic, one settle (zero speed only
   at the end). Remove the zStart < 1 path, the resting underlay and the feathered edge.
2. Desktop project header rests at FLIGHT.zEnd (project-page.js / project.css: the header image's base scale; keep its scroll parallax
   working on top of it). Direct visits show the same zoomed header.
3. No flash / no hold: enable cross-document View Transitions in Chrome for the Work -> project and project -> Work navigations
   (`@view-transition { navigation: auto; }` in both documents, with NO cross-fade animation: the old page's last frame is held until
   the new page has rendered its first frame; use `pageswap` / `pagereveal` if needed to sync the flight). Keep today's sessionStorage
   hand-off as the fallback for browsers without it. Also make sure the project page's first paint uses the EXACT image URL the Work page
   drew (currentSrc), already in the memory / HTTP cache, so it is decoded on the first frame.
4. No stalls: nothing heavier than ~20 ms may run on the main thread during a transition, both directions. On the way back, defer the
   Work page's heavy start-up (layout solve, image activation / texture uploads, GL setup for far items, idle loads) until the back
   animation has finished; during the open, nothing heavy runs either (no new uploads, no navigation prefetch work on the main thread).
   Measure with a PerformanceObserver for long tasks.
5. Engine ownership this round (for R41): make the engine mode-agnostic. Replace the `isTall()` gates inside
   src/effects/project-transition.js (and the hover-only prepare) with a small policy read from settings:

   and a DEFAULT for lite in settings/tall.js set to today's behaviour (enabled: false) so nothing changes on phones in R37f. Document the
   policy fields at the top of project-transition.js. Move bulge-gl.js, flight-curve.js, project-transition.js and the 8 HTML head
   hand-off scripts to SHARED in docs/OWNERS.md (engine), noting "engine changes go through one agent at a time".
