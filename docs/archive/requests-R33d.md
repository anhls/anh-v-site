### 1. Counter = two separate digits (Anh), a real drum on the units
Why: R33b / R33c built two slots that both slide by the SAME fraction with only two faces each (current number, next number), so the tens "0" slides out and a new "0" slides in on every step: it looks like the zero rotates with the number. Anh's design: split the number into two independent digits, "0" and "n".
- DOM / layout: two separate digit elements (tens, units), each its own masked slot (overflow hidden, one digit tall). The TENS is RIGHT-aligned and the UNITS is LEFT-aligned around a shared centre line so the pair stays tight whichever digit is shown (the font's "1" is very thin: with equal fixed slot widths it left a gap; with this alignment the pair always touches the same seam). Keep the R32 numeral font / size / weight (thin, 128 px wide at 1920 for two digits "04"): the visible width for 01..05 must stay within 3 px of R32 for the same number (report the measured ink boxes of 01..05 at 1920 and 2560).
- UNITS drum: a column of the digits 0-9 repeated (at least 3 turns, e.g. 30 digits) so it can turn either way without a seam; its position is the continuous project number; it turns ONE digit per number and shows every digit it passes on a multi-number flick (04 -> 02 forward across the wrap: see below). The 05 -> 01 / 01 -> 05 wrap stays ONE direct roll between the two numbers with no intermediate digit shown (Anh, R33c). Settle `counterSettleSec` 0.35, overshoot 0 default, vertical blur `counterBlurPx` 10 with the same blur rule / timing as R33c (same layers, never toggled off during a visit).
- TENS digit: it does NOT move at all while the tens digit is unchanged. With 5 projects it is a still "0" (no drum, no transform, no blur). Build it as a drum anyway so that when the project count reaches 10 or more it turns "0" -> "1" ALONGSIDE the units at the carry (09 -> 10) and "1" -> "0" back on the way down, with the same blur / settle as the units; give it a dev switch `?n=12` (or a WORK_V2 override) to test with 12 projects (log the positions, include a screenshot strip of 09 -> 10 -> 11 -> 12) without changing the real data.
- Checks: log the position of BOTH drums every frame over a wheel burst, a long flick across the wrap, 05 -> 01, 01 -> 05 and a drag: the tens drum stays EXACTLY at its rest position (0 transform changes, 0 blur) for all of them with N = 5; the units drum equals the nearest project at rest (0 mismatch frames, exactly on a digit); with ?n=12 the tens turns only at the carry. Mid-roll strip screenshot in tools/scratch/r33d-shots/. Reduced motion: cross-fade as before. Accessibility: the single `aria-live="polite"` text with the final number; the drums `aria-hidden`.

### 4. Title shader = the thomasmonavon.com corner-pull shader (Anh); replaces the R33c slice / slant smear
docs/reference/text-fx-label.mov is a screen recording of thomasmonavon.com (the "Gregory Lalle" title and its "01" index entering). The R33c fit (slices + 22 degree slant) was only an approximation: build the REAL mechanism instead, described here in our own words (do not copy their code; the project doc claude/text-shader-reference-thomasmonavon.md has the same description):
- Keep the R33c overlay plumbing (title drawn into a 2D canvas texture from the computed style at the DPR, a quad in the small shared overlay canvas, DOM title hidden with `visibility` while it plays, no pop at the swap, ?fx=0 / reduced motion / ?gl=0 fallbacks, cancel-and-restart on new input). Replace the shader.
- One scrubbed progress value `uProgress` 0..1; the shader folds it to a triangle `p = (0.5 - |uProgress - 0.5|) * 2` (0 at both ends, 1 in the middle): the ENTER runs 0 -> 0.5 and the LEAVE 0.5 -> 1. Output alpha = texture alpha x p.
- Distortion, strongest where p is small: (a) CORNER PULL: the sample UV is pushed away from an attraction point by `normalize(direction) * distance^(-p)` mixed in by `(1 - p)`; the point is the bottom-left (0,0) for the enter half and the top-right (1,1) for the leave half; the UV is CLAMPED to 0..1 so the edge texels streak toward the corner (the faint streak at the lower left in the recording); (b) SIMPLEX NOISE displacement of the UV, `snoise(vec3(uv * 5, time * 0.3)) * 0.2` scaled by `(1 - p)`: the wobbly sheared breakup. Use a standard 3D simplex noise (the public-domain Ashima / Gustavson implementation is fine).
- Timing: ENTER plays at scroll stop over about 1 s (fit to the recording: the effect starts 0.23 s into the clip; ink coverage numbers from R33c still apply: 1 / 9 / 35 / 48 / 63 / 72 / 85 / 97 / 100 % at +0.02 / .07 / .12 / .17 / .22 / .27 / .32 / .37 / .47 s: tune `enterSec`, the progress easing and the noise scale / amount until the coverage curve and the look match on a contact sheet next to the reference frames, clip times minus 0.23 s). LEAVE plays when the strip moves: 0.5 -> 1 over `leaveSec` about 0.3-0.4 s (the title blows out toward the top-right while fading); new input cancels at once and plays the leave from the CURRENT p (one scrubbed value: a reversal mid-way continues from where it is: no stacking, no flash).
- Optional (flag `WORK_SMEAR.hover`, default OFF): the pointer ripple of the reference (a second low-frequency noise near the pointer over the title, eased in over 1 s) so Anh can try it.
- Scale: the title is far larger than the reference label: keep the noise in UV space so the look scales with the text; check the streak / wobble stay inside the centre image rect + the 40 px spill and never reach the info block (tags / year / description).
- Checks: contact sheets for 3 titles (Techcombank, Similac Virgo, Forbes Vanguard) at the clip times in tools/scratch/r33d-shots/, the reference strip next to them; swap without a pop (< 0.5 % of the box pixels differ by more than 8 levels at 1920 / 2560, DPR 1 and 2); frame time 4x CPU with the smear playing (median <= 7.5 ms, state the numbers); ?fx=0 / reduced motion / ?gl=0 0 errors. Remove the unused slice / slant code and tunables (or leave them out of ?tune); the "Title smear" group gets the new numbers, all described.

### 5. Scroll line (Anh; reference https://angusemmerson.com/)
Reference (read from the page): one 1 px line, full height, the text colour at about 10 % opacity (`--vertical-line-opacity`), position fixed, ABOVE the page background; it moves sideways with the scroll progress and eases after it (about 1.3 s ease-out, no snapping); the site also has a ruler of ticks at the bottom and the line is draggable to scrub (we do NOT copy the ruler).
- Build: a thin line element (own DOM node in the Work v2 root, `pointer-events: none`, `aria-hidden`, 1 px wide at 1920 scaled by the screen scale, min 1 device px, off-white at `scrollLineOpacity` start 0.12). Side mode: a VERTICAL line, full viewport height; vertical mode: a HORIZONTAL line, full width, moving top to bottom.
- Position: `x = frac(stripPos / N) x viewport width` (stripPos = the strip position in pitches, unwrapped; N = project count): the line travels across the whole page once per full loop of the list, so scrolling forward moves it one way and back moves it the other way. The movement eases after the strip with `scrollLineFollowSec` start 1.3 (ease out; exactly follows at rest: the line stops 1.3 s after the strip, no drift).
- WRAP (Anh): the line rolls OFF the screen at one edge and rolls back IN from the other side as you keep scrolling in the same direction (continuous looping: it is never reset or faded at the wrap). Implementation: draw TWO line instances (x and x +/- viewport width) so one exits while the other enters, or modulo the eased position with a seam at the edge; there must be no visible jump, no fade or pop at the seam, in both directions, both modes (log the line position per frame over a long flick across the wrap and report the largest single-frame step: it must equal the eased movement, never a jump of about a screen width).
- Layers / look: behind the text field and the images' warp (z-index above the page background, below the text / ruler / counter, the images draw over it: it must not cross the images; or, if that looks wrong, go over everything: put it on a flag `scrollLineOver` default false and screenshot both); never over the switch / Reach out / nav. During a project transition (R25 / R30) it fades with the UI (the same 0.3 s UI fade). Hidden under reduced motion? NO: keep it but without the easing delay (follows directly); ?gl=0 the same (it is plain DOM / transforms, GPU-friendly, one transform per frame only while moving, nothing at rest).
- Optional (flag `scrollLineDrag`, default OFF): drag the line to scrub the strip like the reference (cursor ew-resize / ns-resize); do NOT enable by default; if you build it, it must route through the existing drag / snap path (no second source of truth) and be fully tested (counter order, seam, rest offset); if it is too risky, leave it out and say so.
- ?tune: scrollLineOn, scrollLineOpacity, scrollLineFollowSec, scrollLineWidth, scrollLineOver, scrollLineDrag.
- Checks: line position vs strip position at rest (exactly the same), the eased follow (the position over time after a flick: ease-out, no overshoot), the wrap in both directions and both modes, frame time 4x CPU (median <= 7.5 ms), the line does not move when the strip is at rest, 0 console errors, screenshot at rest / mid-scroll / at the wrap in tools/scratch/r33d-shots/.
