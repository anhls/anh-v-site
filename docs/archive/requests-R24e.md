## R24e [done] (tablet + phone: no toggle, orientation picks the strip, desktop image ratio, no cards): tablet follows the phone practice, and the phone Work page now matches tablet portrait (use Sonnet 5.5, quick mode, after R24d; R24c follows it)
Goal (Anh, after testing R24b on a tablet): the strip toggle is redundant, the cards are redundant, the project image should keep the desktop ratio. Tablet = whatever R24b already classifies as tablet (reuse its test, do not invent a second one). Added by Anh: the PHONE Work page (tall mode) must match the tablet portrait one: same frame rule (item 3), same no-cards, same warp, same strip behaviour, so phone and tablet portrait are one code path with one set of knobs, not two. Desktop wide mode and the homepage are untouched.
1. Remove the toggle: the R24b 44 px toggle, its handler, styles, state, any storage of the choice and every doc / `?tune` mention. No replacement control.
2. Orientation decides the mode: tablet landscape (aspect >= 1.05) = the wide-style Work strip (the R24b landscape layout path, 3:2 and 4:3 and 16:10), tablet portrait (aspect <= 0.95) = the tall mode of R24a / R24d (phone-style strip, project pages stacked). Dead band 0.95-1.05 keeps the current mode (as `layout-mode.js`). `?mode=tall|wide` still forces. At load the mode follows the current orientation. A rotation while the page is open is R24c's job (live switch): until R24c is built a rotation needs a reload, keep the code ready for it (one place that decides the mode, no module-level constants that freeze it).
3. Lock the project image ratio to the desktop frame: take the ratio from the desktop frame constants (do not hard-code a number; read it from timeline.js / the frame size the wide mode uses at 1920x1080). On tablet in BOTH orientations the frame keeps that ratio, scaled to fit the available area (width or height, whichever limits), centred, never stretched or cropped to the device aspect. Tall mode (phone AND tablet portrait): the frame width is `TALL.frame` of the viewport width (R24d knob, one value for both, default now 0.80, tunable in `?tune`; replaces the R24d 0.72 and the phone-specific sizing), the height follows from the desktop ratio, centred vertically in the strip. No `frameTablet` knob. Landscape: `TABLET.frameH` fraction of the viewport height (default 0.62, tunable).
4. No cards on tablet in either orientation, same as R24d: no card DOM, textures or card layer (`TALL.cardsMaxTablet` 0 and a matching `TABLET.cards` 0 for the landscape path). The landscape tablet layouts, solver and gate (`layouts-tablet.json`, the R24b solver / check) must work with zero cards: frame and strip positions only, spacing / pairs rules skipped. Wide desktop layouts and `layouts.json` untouched.
5. Warp on, as R24d: the R22h image warp driven by real strip speed (touch drag / coast / snap), flat at rest, the R24d frame-time guard (`TALL.guard`) shared by the landscape tablet path, `tallGuard` field in `?perf`.
