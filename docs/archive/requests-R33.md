## R33 (WORK v2 polish: fixed text field, hover enlarge + push, analog counter, ruler motion, R26 pointer on the project image) (use Sonnet 5.5, quick mode; branch `work-v2`: commit there, never merge to main)

Builds on R32 (src/work/v2-ui.js, WORK_V2, WORK_UI, WORK_TITLE). Desktop Work v2 only; phone / tablet lite pages, the card code and main are NOT touched. Gates that must stay green: layout:check, build, compare 542/542 at 1920 and 2560, R30 flow (forward / return, margin, 0 pops), seam 0.00 px, rest offset 0.000 px, frame time 4x CPU median <= 7 ms at 1920 and 2560, ?gl=0 and reduced motion (0 errors). Every number below is a tunable in ?tune (group "Work v2") with a description in tune-docs.js.

### 1. Text field stays in place (Anh)
- The title, tags, year, description (and the counter) are fixed at their R32 reference positions. They do NOT move with the strip, do not slide, do not scale with the image and do not move when the image enlarges (item 2). Today they follow / fade by distance: remove that.
- While the strip moves (wheel, drag, coast, snap) any text that is about to change blurs out and fades (blur radius `textBlurPx` start 12 px, opacity to 0, `textOutSec` start 0.25 s). The text content swaps to the project that is nearest the centre only while hidden. When the strip is at rest and the next image is in focus (the same restOk + focusDelay idea as the lite Work page) the new text refocuses in place (blur 0, opacity 1, `textInSec` start 0.5 s) and the project NAME starts its entrance animation at that same moment (keep the existing name reveal; if there is none, a rise + refocus of the same length).
- Max one text set visible at any time; a quick reversal while refocusing re-blurs from the current value (no jump). Reduced motion: 0.2 s fade, no blur. ?gl=0: same (CSS filter is fine, no GL needed).

### 2. Hover enlarge + push away (Anh)
- Hovering the CENTRE project image (pointer fine + hover capable only; off for touch and pen) enlarges it subtly: `WORK_V2.hoverScale` start 1.04, spring / ease with `hoverSec` start 0.6 s (slow, soft), back on leave.
- The side images are pushed outward by exactly the growth, so the gaps stay 57 px (side mode) / 75 px (vertical mode) and nothing overlaps: the centre grows around its centre, the neighbours' positions get an offset of (scale - 1) x half the image size along the strip axis plus the same on their near edge. Warp, seam and counter order must not change; check the seam stays 0.00 px with the push on and off.
- Disabled while the strip is moving or dragging (the scale eases back to 1 first), and while a project transition runs. A click eases the scale back to 1 over 0.15 s as the R25 transition starts (so the FLIP rect the transition reads is the unscaled frame: verify the R30 flow margin unchanged and 0 pops). The hit area is the image rect, not the text field.
- Text field positions must not change with the hover (item 1).
- ?tune: hoverScale, hoverSec, hoverOn.

### 3. Analog counter, with blur (Anh)
- The big numeral becomes a mechanical digit roller (odometer): each digit is in its own masked slot (overflow hidden, one digit tall) with a column of digits 0-9 that rolls vertically. 01 -> 02 rolls only the last digit; 05 -> 01 rolls the units backwards through 04, 03, 02, 01 (direction follows the strip direction). The small "/N" stays still and sharp (N = the real project count).
- It rolls WITH the strip: during a flick the digits pass every number between the old and the new value (roll speed follows the number of projects passed per second, capped at `counterMaxSteps` per second so it stays legible), then eases out onto the target as the strip lands, with `counterSettleSec` start 0.35 s ease-out (a very slight overshoot of 0.04 digit height allowed, tunable, 0 = none).
- While rolling the digits get a vertical motion blur (CSS `filter: blur()` on the column, or a stacked-offset trick if that is cheaper), strength proportional to the roll speed up to `counterBlurPx` start 6 px, 0 when the digit has landed; it sharpens together with the title refocus of item 1. The counter does NOT use the text blur-out of item 1 (its own motion replaces it).
- Counter order check: 0 non-unit steps over the 4 wheel patterns x 2 modes (as in R32), the visible digit always equals the project nearest the centre at rest. Digits use the R32 numeral font and size (thin, 128 px wide at 1920 for two digits). Reduced motion: cross-fade as in R32. Accessibility: one `aria-label` / `aria-live="polite"` text with the final number, the rolling columns `aria-hidden`.
- ?tune: counterSettleSec, counterBlurPx, counterMaxSteps, counterOvershoot.

### 4. Wordmark / logo (Anh)

### 5. Ruler motion (Anh)
- Replace the current ruler change with this sequence when the project in focus changes: the tall bar (the current project) SHRINKS down to a dot (`rulerShrinkSec` start 0.25 s), DIMS (opacity down to the dot opacity) and MOVES with the strip to its place; the NEXT dot moves into the bar's place, LIGHTS UP and GROWS into the bar. The last part (light up + grow) happens ONLY when the new project is in focus (rest + focusDelay, the same moment as the title refocus and name entrance, item 1), not earlier: until then no bar is shown (all dots, dim). `rulerGrowSec` start 0.4 s, ease out. On a long flick the dots keep scrubbing with the strip as in R32 (the bar position follows the strip, only the bar's grow waits for the focus). Window rule from R32 stays (3 dots + bar + 3 dots, window min(N, 7), odd).
- ?tune: rulerShrinkSec, rulerGrowSec, rulerDimOpacity.

### 6. R26 pointer interaction on the project image (Anh; R27 text animation is NOT part of this)
- The centre project image reacts to the mouse: a velocity smear along the pointer direction plus a pixel-shader distortion trail that fades to exactly 0 (small offscreen displacement field in the frame's own UV space), optional RGB shift. Anh chose smear + distortion trail (not grab-and-stretch).
- Rules: field resets on project swap; eases to 0 in about 0.15 s on click (so the transition reads a clean frame); capped TOGETHER with the scroll warp (the sum never exceeds the warp's clamp, check with the grid twin: 0 folds, 0 samples outside the buffer); off for touch, ?gl=0, reduced motion and weak devices; skipped when idle (zero cost: no pass when the field is 0 and the pointer is still); drag vs click threshold ~5 px; works with the hover enlargement (item 2) in the same frame: the displacement is computed in the image's own UV space so it scales with the image.
- Only the centre image of the Work v2 page. NOT the side images, not the homepage, not the hero (that stays a flag in timeline.js, off).
- Tunables (?tune): smear strength / length / start speed, distortion strength / brush radius / decay, field resolution, RGB shift, spring stiffness / damping, overshoot.
- Check: pixel-identical to R32 at rest with the pointer still, frame time 4x CPU with the pointer moving continuously (median <= 7.5 ms, state the number), the field is exactly 0 within 1.5 s after the pointer stops, screenshots of 3 strengths in tools/scratch/r33-shots/.

### 7. Warp axis lean on scroll DOWN only (Anh, after using it)
- Scroll DOWN = the strip direction that a wheel-down (positive wheel delta) and a downward keyboard / drag-equivalent produce (side mode: strip moves right to left; vertical mode: its own wheel-down direction). For that direction ONLY, the axis lean (frameWarp `uShift`, `leanSign`) flips: the axis leans AGAINST the motion instead of toward it. Scroll UP keeps today's lean (toward the motion) exactly: same values, same sign, pixel-identical to R32 for upward movement.
- The warp itself is unchanged in BOTH directions: same bend, same amount curve (speed-curve.js), same strength / curl / cam / bow. Only the sign of the axis shift for the down direction changes. The buffer cap (lean-limit.js) must be re-checked for the flipped side: the lean toward the strong side (about 0.25 desktop) is now used when scrolling down; keep 0 folds and 0 samples outside the buffer with the grid twin (121x121, both axes, both directions, amounts -2.4..2.4), and report the effective shift for down and up at full warp.
- Implementation hint: a separate sign per direction, e.g. `frameWarp.leanSignDown` (start -1 = against the motion) and `leanSignUp` (start +1 = as today), in ?tune, so Anh can flip either by feel; the transition between directions (reversal mid-scroll) stays continuous (largest 1-frame shift change <= 0.017 as in R24i), and rest is exactly 0.
- Applies on desktop Work v2 (both modes). The phone / tablet lite pages keep today's behaviour unless the same flag is set there (default: unchanged).
