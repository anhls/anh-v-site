### 2. Pixel smear, Codrops grid method, on ALL images, out of bounds (Anh)
Reference https://tympanus.net/codrops/2022/01/12/pixel-distortion-effect-with-three-js/ : a low-resolution grid (DataTexture) where each cell stores an x / y displacement; each frame the cells within a brush radius of the pointer receive the pointer velocity, every cell relaxes (x 0.9 per frame, frame-rate independent here), the fragment shader samples the picture at `uv - strength x offset.rg`. The look is BLOCKY pixel smear (stepped cells), not the soft gaussian of R33.
- Replace the R33 smooth field in work/pointer-fx.js with this grid method. ONE screen-space grid covers the whole strip area, not one per image: the brush works on whichever image the pointer is over and a sweep across a gap carries onto the neighbour. Cells: `pixelGrid` start 32 columns (rows by the aspect), nearest filtering so the steps stay visible; brush radius `pixelBrush` start 0.12 of the frame height; strength `pixelStrength` start 0.04 UV; relaxation `pixelRelax` 0.9 per 1/60 s; velocity input clamped (`pixelVelMax`) so a fast flick cannot tear the picture; optional small RGB split kept (`pixelRgb`, start 0.01).
- All images get the smear, side images with a multiplier `pixelSideMul` start 1.0 (0 = centre only). Zero cost at rest: no grid update, no texture upload and no extra sampling while the grid is exactly 0 and the pointer is still; the grid snaps to 0 below an epsilon (exactly 0 about 1.5 s after the pointer stops).
- OUT OF BOUNDS: the displaced picture is allowed to draw OUTSIDE the image rectangle, like the reference screenshot where the bottom edge of the Forbes picture is a wavy curve about 40 px below the frame edge (the content's edge pixels are pushed out; the frame is not a hard clip). Implementation guide: draw each picture quad with a margin (`pixelSpill` start 40 px at 1920, scaled by the screen scale; padded geometry or a larger quad), sample with clamp-to-edge on the picture's own UV, and discard pixels whose distorted sample is outside the picture UV 0..1 BY MORE than the displacement allows, so only displaced edge pixels spill (an undisturbed picture is pixel-identical to R33 / R32: same rect, same edges). The spill is clipped at the neighbour's rectangle (images never draw over each other) and never touches the text field (cap by the info band: the image zone stays between its y limits; check the margin does not cover the tags / year / description at 1920 and 2560, both modes). The side strips stay one canvas as today.
- Rules carried over: field resets on a project swap / when the strip moves or morphs (gate 0.15 s), eases to 0 on a press / drag / transition, capped together with the scroll warp (the warp factor scales it so no new fold), off for touch / pen, ?gl=0, reduced motion and weak devices. Click still reads the unscaled FLIP rect (R30 flow with the mouse over the image, margin about 105 px, 0 pops).
- Checks: rest identical to R33 with the pointer outside (max diff 1 level, grain off); with a still pointer 0 extra passes (log); frame time moving pointer (median <= 7.5 ms at 1920 and 2560, 4x CPU, state the numbers); field exactly 0 within 1.5 s; screenshots in tools/scratch/r33b-shots/ at weak / default / strong and with the pointer over a side image (spill visible on the bottom edge, no overlap with a neighbour or the text).

### 5. Counter: a true analog drum counter (Anh: the R33 counter is not what was described)
R33 built two stacked numbers per slot that slide into each other, with a spring that overshoots, a 6 px blur, and a list that wraps (05 -> 01 = one step forward). Replace with the original description:
- Each digit slot (units, tens) is masked to one digit tall and holds a DRUM: a vertical column of the digits 0-9, repeated (at least 3 turns, e.g. 0-9 x3) so it can turn either way without a visible seam. The slot shows the digit at the drum position; the drum position is a continuous float.
- The counter rolls through EVERY value between the old and the new project, in the direction of travel, with no wrap shortcut: 01 -> 02 turns only the units drum one digit; 05 -> 01 (a flick backwards through the whole list, or after the last project) unwinds 04, 03, 02, 01 and shows each digit passing; 01 -> 05 turns forward through 02, 03, 04, 05. The units drum turns on every number; the tens drum only turns when the tens digit changes (never for 01..09, so it stays at 0).
- The roll follows the strip while it moves: the drum position tracks the nearest-project number as before (lag cap, `counterMaxSteps` per second so it stays legible on a hard flick), and eases onto the target when the strip lands: `counterSettleSec` 0.35 ease-out, `counterOvershoot` default 0 (keep the slider; 0 = none). No spring bounce by default.
- Blur: vertical motion blur on the rolling digits, peak `counterBlurPx` 10 (not 6), proportional to the roll speed, 0 when settled; it sharpens together with the text (item 1: the same blur-out timing at rest). The "/N" and the label stay still and sharp.
- Keep: the R32 numeral font / size (thin, 128 px wide for two digits at 1920), the masked slot alignment, reduced motion = cross-fade, `aria-live="polite"` text with the final number and the drums `aria-hidden`.
- Checks: the visible digits equal the nearest project at rest (0 mismatch frames, 0 non-unit steps) over the 4 wheel patterns x 2 modes AND the wrap cases 05 -> 01 and 01 -> 05 (log the digits shown during the roll: they must pass 04, 03, 02 and 02, 03, 04), the drum position is exactly on a digit at rest, no seam when turning either way (screenshot strip of the drum mid-roll in tools/scratch/r33b-shots/).
