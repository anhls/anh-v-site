PART 1 (fixes).
P1.1 Drag then rest must end centred. Bug (Anh, screenshot): after a mouse drag the strip often stays stuck about 0.33 of a pitch off centre (Bitis left of centre, Sulwhasoo right of it, counter 02 / 05): the soft snap never engaged. WORK.snapWindow is 0.5 (any position qualifies), so after snapDelay (1 s) of quiet and |vel| < 250 px/s the snap should always take over. Reading the code finds nothing obviously wrong, and the R22e / R22g tests never waited after a release to assert the end position (the R22g hunt skipped the drag frames). Reproduce with a REAL mouse in Playwright (press, move, release) in both modes at several speeds and start positions: a slow release (no inertia), a medium one, a hard fling (inertia + overshoot), a release exactly between two projects, a drag that ends on a card; after each wait 3 s and assert the strip ends centred on a project within 0.5 px. Log every frame: lastWheel age, vel, snap, inertia, drag, lenis targetScroll - animatedScroll, snapOk, so the gate that keeps the snap from firing is identified; suspects: (a) vel stays >= 250 after a drag (dragAccum is added into vel), (b) something keeps refreshing lastWheel at rest (a stuck drag / inertia state), (c) the predicted target uses a leftover Lenis glide (pred = S + (targetScroll - animatedScroll) x wheel), (d) an event after the release (click, pointer) cancels the snap. Fix the cause; keep the assertion as a regression test (tools/scratch). Also run the same rest assertion after a plain wheel scroll and after a toggle, in case the cause is not drag-only.
P1.2 Toggle settle without a second push. Bug (Anh): after the toggle the cards move, then suddenly accelerate and get pushed away. Cause (R22g): cards move on a plain ease that slows to nearly a stop, then get a velocity shove at arrival (ramped over 0.14 s), so a nearly stopped card speeds up again and slides off; the ramp avoids a speed step but not the second push. Fix: overshoot must come from momentum that was already there: the approach must not slow to zero first. The card arrives with the speed it still has, passes its place and comes back (the pushed-and-settling feel), the speed profile is continuous and there is no new push at arrival. Claude Code picks the cleanest way (an ease for the cards that ends with residual speed feeding the spring, or the spring following the eased target). The settle size still follows the move's force (R22g: small movers hardly overshoot, far ones more). The images' overshoot gets the same test. Test per item over the whole morph and settle: speed must NEVER rise again once it has started to fall, until the direction reverses at the overshoot's peak; no step in acceleration above a small threshold (state it); each card passes its place once and comes back; it ends exactly on its place (0 px) with no jump at start or end; both directions (side to vertical, vertical to side), 1920 and 2560, forced samples at the large and small travellers.

PART 3 (ambient drift, slow drift toward the next project while at rest). Feasible, Anh asked for it. Design:
P3.1 It is a separate visual offset (like the mouse drift), NOT a scroll: moving the real strip position would make the soft snap see the project off centre and pull it back (ping-pong). The snap, the counter, the focus and the seam are unaffected. Once the strip has rested and the focus has built (WORK.ambDelay, start 2 s) an offset eases in toward the NEXT project (the forward strip direction) and approaches a small maximum slowly (WORK.ambTau, start about 15 s, exponential approach); the main image travels at most WORK.ambFrame (start 20 px at 1920, scaled with the capped scale), the cards ambCardMul times that (start range 2 to 4.5, see P3.2), nearer (higher depth) cards further (the same depth weight as the mouse drift). Any wheel / key / drag / toggle eases every offset back to zero over WORK.ambReturnSec (start 0.8 s) along the ease curve (no pop); the next rest starts it again. It renders only while moving and stops once it has settled at its maximum. Reduced motion and ?gl=0: no drift. R25 transition and the focus effect are not affected (the overlay reads the current positions).
P3.2 Variation in the cards' movement. Per card, seeded from its own hash + the seed (same seed = same motion; adding an image changes no other card): amount (travel multiplier drawn from ambCardMulMin 2 to ambCardMulMax 4.5, times the depth weight), speed (its own time constant, +-ambTauVar 0.3 around ambTau), start delay (up to ambStagger 1.5 s), direction (the main direction is toward the next project, plus a small cross-axis component up to ambCross 0.25 of its travel, positive or negative, so the cards fan out slightly), and an optional very slow tiny sway along the cross axis (ambSway, a few px, its own seeded period; default 0 = off). The main images keep ONE smooth drift with no variation (the steady image against the varied cards is what the eye picks up). Any input returns every card to zero along the same curve, each from its own offset, no pop.
P3.3 Overlap rules (R22e): each card now has its own maximum travel, so the check uses per-card extents at maximum drift (incl. the cross-axis part and the sway), together with the mouse drift corners; the fix pass nudges a card if its own extent would make a triple stack, a dark-on-dark overlap above darkOverlapMax or a pair above pairOverlapMax; keep the maximum card travel small enough that these hold (report the numbers; if they cannot all hold at the starting values, say so and propose smaller ones).
P3.4 Tunables in WORK and ?tune: ambDelay, ambFrame, ambTau, ambReturnSec, ambCardMulMin, ambCardMulMax, ambTauVar, ambStagger, ambCross, ambSway. Checks: the offset eases in and reaches its maximum, any input returns it to 0 with no jump (frame by frame), per-card amount / speed / delay differ and match their seeds, the same seed gives identical motion on reload, adding an image changes no other card, overlaps hold at the maximum offsets (seed 3 plus about 5 others), the snap still ends 0-0.4 px, counter order, seam 0.00 px, frame time with 4x CPU throttle (also while drifting), npm run compare unchanged.
