### 1. Blur glitch (Anh: "the blur is glitchy when the strip moves and in animation")
Not reproduced by Cowork: FIND THE CAUSE FIRST (record frames of the text blur while wheeling, during the 1.3 s blur-out and during a drag; log filter values per frame; check for steps, flashes, a frame at blur 0 between values, a pop when the content swaps), then fix and REPORT the cause. Likely suspects: the 0.1 px threshold that switches `filter` on / off (a layer promoted and dropped each time = a flash), the counter's SVG filter (`url(#w2-vblur)`) toggled with `none`, the text swap happening while the blur is still ramping (swap only after a short hold at full blur, `swapHoldMs` start 60 ms), the blur radius changing every frame on large text layers (quantise to 0.5 px steps, update only when the quantised value changes), the title and info on different compositor layers with different timing. Guide for the fix: keep one continuous `filter: blur()` on its own layer (`will-change: filter` while animating, removed at rest), no on / off toggle, the value eased and quantised, no opacity change, the counter uses the same CSS blur (or a stable SVG filter that is never removed during a visit), and a visible-glitch test: sample the computed blur every frame over wheel, drag, blur-out, interrupted blur-out and a quick reversal: it must be monotonic inside each ramp (no jump larger than 1.5 px per frame at 60 Hz).
