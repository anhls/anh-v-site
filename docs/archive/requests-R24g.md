1. Weak-device rule (src/util/device.js, used by cards-gl / frame-gl / back-to-top): `navigator.hardwareConcurrency <= 4` flags every iPhone (iOS reports 4 or 6 cores whatever the chip; his own bench shows 7-9 ms for the JS test). 2. Real flick inertia on touch in the lite modes. Today (work.js endDrag): release speed = the last drag speed, coast only if > 30 px/s, friction `WORK.dragFriction` 0.6 s (speed x exp(-t / F)), the coast is capped at `WORK.dragMaxCoast` 1.5 pitches, and the soft snap starts `WORK.snapDelay` 1 s after `lastWheel` (a release sets it). That is a short, capped glide: a hard swipe ends in about one image and never reaches high speed, so the warp (which follows speed) stays weak. For the lite modes add TALL overrides (desktop values untouched): 
   a. Release speed from a velocity window: keep the pointer samples of the last 100 ms (time + position along the strip axis), speed = displacement / elapsed over that window (needs at least 2 samples; ignore a stop of more than 80 ms before the release = no fling).
   b. `TALL.flingGain` (default 1.3) x the release speed, in screen lengths so a phone and a tablet match (work in px but scale by `warpRefPx / screen length along the strip`).
   c. `TALL.dragFriction` default 1.1 s (longer glide), `TALL.dragMaxCoast` default 4 pitches, `TALL.flingMin` 0.3 screen lengths/s below which there is no coast.
   d. The soft snap must not cut the glide: in lite modes it starts only when the speed has fallen under `TALL.snapAfterSpeed` (default 0.25 screen lengths / s) AND `TALL.snapDelay` 0.35 s have passed since the last movement (not 1 s from release, which now arrives while it still glides); the snap target is the project the coast is heading for (the existing R22i magnet may be reused with `dragSnapBlend`). No overshoot jumps, the seam, the counter order and the centred rest are unchanged.
   e. A light swipe still lands on the next image, a firm flick glides 2-4 images and the counter steps by 1 the whole way.
